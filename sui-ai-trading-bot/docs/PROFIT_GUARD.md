# ProfitGuard：mainとの差分と設計・検証

調査対象：取得時点の `origin/main` = `a7339d8`。未マージのLIVE基盤とは別の `codex/profit-guard` ブランチで実装。

## 既存実装との差分

| 対象       | 既存main                                   | 追加した動作                                                                                       |

| 戦略       | 価格条件による損切り/利確SELLが同じ理由    | 条件は維持し、STOP_LOSS / TAKE_PROFIT / STRATEGY_EXITの目的を追加                                  |

| PAPER      | 原価に入力USDC+追加手数料+ガス相当額を合算 | 数量atomic、原価decimal、追加費用・DEX費用の内訳/不明フラグを約定に保存                            |

新規 `packages/profit-guard` はSDK/DB/HTTP/署名に依存しない計算モジュールです。将来のLIVEも実受取数量・実支払原価・見積もり・費用を同じ契約に正規化して利用できます。この変更はLIVE実装・実ウォレット・署名・送信を追加しません。

## 金額と手数料の扱い

- 数量はSUI atomic（9桁）、USDC見積もりはatomic（6桁）。金額はDecimalの専用constructorで60桁精度。指標やSDKのグローバルDecimal設定は変えません。
- 追加費用はUSDC小数6桁に切り上げ、純利益は切り下げ。部分売却の原価も切り上げ、その分を残余原価から引き、最終売却では残余を全額配賦します。
- 総取得原価 = 入力USDC + 追加約定手数料 + ガス相当額。DEXルート費用は入力額・出力数量へ既に反映されているので二重加算しません。
- PAPERで保存する「実際の取得原価」は、仮想口座から実際に控除した金額です。追加手数料/ガスはPAPERのモデル値です。実オンチェーンの費用実測ではありません。
- 現行Cetus SDKの見積もりから実DEX手数料を正確なUSDC内訳へ分解できないため、`dexFeeUsdc:null` と明示して保存・表示します。費用がゼロという意味ではありません。最低受取額へ含まれているため、その内訳不明だけで純利益計算を不可能とは扱いません。
- ガスまたは追加費用が不明、見積もりが取得不能/不正/古い場合、利益目的のBUY / SELLはWAITです。

売却純利益 = 最低受取USDC − 売却分の取得原価 − 売却追加手数料 − 売却ガス相当額。

利益率の分母は売却分の総取得原価です。全保有分ではありません。UIには全保有分の原価と見積もり対象分の原価を分けて表示します。旧履歴の取得原価総額は引き継ぎますが、存在しない内訳を推測して埋めません。

## BUY前のモデル

1. USDC→SUI見積もりの最低受取SUIを仮想取得数量とする。
2. その数量に対するSUI→USDCの最新見積もりを取得。
3. 今すぐ往復した場合の総費用を推定。
4. 現在の逆方向最低受取額を、想定利確価格/現在価格の比率で拡大したシナリオを作る。価格は設定上の上昇シナリオと、既存戦略が取得原価ベースで発火する利確価格の低い方を採用。
5. 1注文の上限により将来の売却が複数回になる場合は、その回数分のガスと保守的な手数料丸めを見込む。
6. 想定純利益が最低額・最低率を満たし、かつ想定往復コストを**上回る**場合だけBUY候補を通す。

これは将来の流動性・価格影響・ガスを予測するものではありません。価格比によるコストモデルであり、利益を保証しません。実SELL時には必ず最新見積もりで再判定します。

損益分岐価格も現在の見積もりの費用比率が続くというモデルです。全保有数量の確実な売却価格ではなく、その見積もり対象数量についての目安です。

## 設定・画面

Settingsの専用入力とJSONから変更できます。旧設定には読み取り時にデフォルトを補完します。

```json
{
  "profitGuardEnabled": true,
  "minNetProfitUsdc": 0.05,
  "minNetProfitPct": 0.01
}
```

最低純利益0.05 USDC、最低利益率1%。BUYシナリオの上昇率は既存のtakeProfitPctを再利用します。無効化は利益閾値のみを解除し、費用不明の利益注文やRiskEngineの拒否は解除しません。

処理順は Strategy → 最新DEX見積もり → ProfitGuard → RiskEngine → PAPER約定です。STRATEGY_EXITは既存の下落シグナルによるリスク削減として、赤字でも利益条件を適用しません。STOP_LOSS・RISK_REDUCTION・EMERGENCY_EXITも同様です。理由文から推測しません。

Overview / Strategyに平均取得単価・現在価格・損益分岐価格・純利益・利益率・費用・判定理由を表示します。計算不能時はSELL目的にかかわらずWAITとします。保護的SELLが免除できるのは最低利益額・最低利益率のみで、安全性検証は免除しません。

ProfitGuardがWAITへ変更しても、元の戦略判断はstrategy_decisionsに保存します。実効判断と理由はdecision、利益判定履歴はprofit_assessmentsに保存します。既存の同一確定足の重複抑止・一括保存・緊急停止は維持します。

緊急停止ボタンは従来通り「新規注文を止める」操作であり、自動的な強制売却は追加していません。EMERGENCY_EXITという目的で将来SELLを作る場合、ProfitGuardは妨げませんが、停止状態や見積もりなど既存の実行前検証は別途必要です。

最初に計算契約テストを追加し、モジュール未実装による失敗を確認。その後実装しました。さらに「戦略より遅い利確価格の仮定」「未知のSELL目的での利益条件回避」について、失敗するテストを先に追加してから修正しています。

既存バックテストの約定時点・戦略・評価手順は維持しています。新しいPAPER会計では費用をUSDC単位で保守的に丸めるため、過去のfloat計算との差がサブmicro〜micro USDCで生じる場合があります。バックテストでは過去の実DEX見積もりが存在しないため、**新しいProfitGuardの注文抑制は自動適用していません**。バックテスト結果をProfitGuard付き運用の収益性検証済みとは扱わないでください。

実行：`pnpm build` / `pnpm test`。通常Workerへの反映には再起動が必要です。既存の稼働中Workerや`.env`はこの作業で変更・再起動しません。

## P0：保護的SELLの安全性検証

全SELLで設定、最新見積もり、SUI→USDC方向、正のatomic数量、最低受取額、保有数量、取得原価、ガス代・追加費用を検証します。例外時は必ずallowed=false / WAITです。STOP_LOSS・STRATEGY_EXIT・RISK_REDUCTION・EMERGENCY_EXITは検証成功後に限り利益閾値を免除します。Profit Guard無効時も安全性検証を免除しません。

拒否理由はQUOTE_UNAVAILABLE / QUOTE_EXPIRED / INVALID_QUOTE / UNKNOWN_COSTS / INVALID_POSITION / INVALID_PROFIT_CONFIG / INSUFFICIENT_POSITIONに区別します。外部例外のメッセージや応答本文をログへ渡さず、固定コードをprofit_assessmentsに保存します。実行候補の拒否はpaper_ordersとrisk_eventsにも記録します。元のSELL判断はstrategy_decisionsに残し、実効判断はWAITとして保存します。

現行PAPERではProfitGuardを通過した候補も既存RiskEngineで審査します。将来LIVEを追加するときは `Strategy → Quote → ProfitGuard → RiskEngine → TransactionSimulation → Execution` を必須とし、ProfitReport.allowed単独を実行承認として使ってはいけません。シミュレーション未実施・失敗のLIVE実行経路を設けないことが導入条件です。今回LIVE実行経路は追加しません。

回帰テストでは不正データによる拒否と理由コード、有効データでの保護的赤字SELL、Workerの約定ゼロ・元判断/拒否履歴保存を確認します。過去の利益判定履歴は書き換えません。稼働中Workerへの修正適用には再起動が必要です。
