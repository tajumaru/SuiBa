# 振り返りレポート（段階1）— 2026-11-08

## 目的

「検証を繰り返すたびに強くなる」ための土台。検証ランの判断記録を、後の価格と突き合わせて機械的に集計し、売買条件の値打ちを証拠として貯める。レポートは証拠専用で、**売買ルールは自動では変えない**。変更は常に「証拠 → 提案 → オーナー承認 → 反映 → 次のレビューで再測定」の順。

## 仕組み（トークン不要・タップ不要）

1. EXPORT-PAPER-PUBLIC で判断記録（SUI_USDC.sqlite）を公開 artifact 化する（従来どおり承認1回）。
2. ワークフロー `SuiBa run review (stage 1)`（suiba-paper-review.yml）を export の実行 ID 指定で起動する。ゲート変数は `SUIBA_PAPER_REVIEW_ENABLED`。VPS には接続せず、承認も不要。
3. `docker/run-review.py`（標準ライブラリのみ）が DeepBook Indexer の5分足を取得して集計し、定型レポートを生成。ワークフローが専用 Issue（ラベル `suiba-run-review`）へコメントとして積み上げる。

手元で直接回す場合: `python3 docker/run-review.py <SUI_USDC.sqlite> [--candles candles.json] [--out report.md]`

## 集計内容

- 判断の内訳（action／selectedRule）と対象期間の価格変化。
- BUY の3条件（EMA上昇・RSI回復・MACD改善）の充足数別に、その後 +1h／+4h／+24h の価格変化（平均・中央値・プラス率）。
- 「あと1つで買えた」判断への仮想タッチ（24h 以内、利確 +1.5%／損切り −1.0% の先行数）。
- 条件ごとの値打ち：ちょうど1条件だけ欠けた判断のその後（どの条件が関門として効いているか／緩和候補か）。

## フラグ（v1 の目安、機械判定）

- **candidate**：単独欠けの標本 n≧30 かつ +4h 平均 ≧ +0.30% かつ プラス率 ≧ 50%。「緩和候補として判断材料が揃った」合図。
- **caution**：「あと1つ」全体の標本 n≧30 かつ +4h 平均 ≦ −0.30%。「現行の厳しさが守っている」側の証拠。

閾値は初期の目安であり、標本の偏り（1つの相場つきだけ等）がある間はフラグ単独で変更を決めない。段階2の提案には、複数局面にまたがる再現を要する（ML 監査の段階基準と整合）。

## 初版の実測（2026-11-08、11/3〜8 の判断 482 件）

- 全て WAIT・約定0。SUI は −3.41% の下げ相場。あと1つの41件は買っていたら +4h 平均 −0.71%、仮想損切り先行 35 vs 利確 6 ＝買わないのが正解だった。
- RSI回復だけ欠けた36件はプラス率 3%（効いている関門）。EMA上昇だけ欠けた5件は全てプラスだが n=5 で結論なし、今後の標本待ち。

## 注意

- その後の価格変化は手数料・スリッページ・ProfitGuard 未考慮の素の値動き。
- export は「最新ランの開始時点のバックアップ」なので、直近ランの判断は次の export から材料に入る。
- +24h は直近判断ぶんが未経過の間は標本が減る。

## 局面タグと期間フィルタ（2026-11-08 追加）

- 各判断に局面タグを付ける：5分足終値の EMA50 について、判断時点と24時間前の傾きが +0.5% 以上で「上昇」、−0.5% 以下で「下降」、間は「横ばい」。足が24時間分届かない判断は「不明」。レポートに局面別の件数と「あと1つ」の +4h を出す。
- `--since` / `--until`（ISO 日時＝UTC、または epoch 秒）で判断を期間に絞れる。特定の検証ラン（例：ハードプリセットを当てたラン）の区間だけをレビューする用途。
