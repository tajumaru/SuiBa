# PAPER復旧ステートマシン

基準: main 1f69022。既存のタイムアウト、再試行、45秒取得期限、単一tick、世代番号、原子的fillを維持。

| 状態                  | 入力・条件                                                      | 次状態 / 注文                                |
| --------------------- | --------------------------------------------------------------- | -------------------------------------------- |
| HEALTHY               | 証拠付き一時通信障害                                            | DEGRADED、running=false、世代更新、注文禁止  |
| DEGRADED / RECOVERING | 通信再失敗                                                      | DEGRADED、正常周期数をゼロへ                 |
| DEGRADED / RECOVERING | 市場・Sui・注文・台帳が正常、backoffなし                        | RECOVERING、独立した正常周期を加算           |
| RECOVERING            | 2周期以上・初回正常から60秒以上・周期間30秒以上                 | HEALTHY、PAPERかつ再開意思が残る場合のみ再開 |
| 任意                  | 手動停止・緊急停止・データ異常・台帳異常・注文不明・180秒/9失敗 | 再開意思を取り消し停止、人による確認が必要   |

市場証明は全時間足の未解決欠損ゼロと当該周期の取得、10秒以内の板、Indexer遅延60秒以内、fallbackなし。Suiも当該周期の新規正常確認を要求。回復確認周期では発注しない。

今回の差分は復旧時の注文照合。PAPERには非同期未確定注文が存在しないため、FILLEDはtradeと成功checkが各1件必要。REJECTED以外の不明状態、孤立trade/check、失敗checkは自動再開不可。既存データに不整合がある場合も保守的に止まる。

WindowsでローカルNode 24.22.1を明示指定してモック試験。Dockerの定義・通信期限・リスク制限は変更しない。実通信や実資金の成功を示す検証ではない。

追加補強: market/Sui証明不足またはbackoff中の周期では正常周期の蓄積をリセットする。間に不完全な周期を挟んだ正常観測を連続復旧と誤認しない。

検証結果: Windows / Node v24.22.1。`node scripts/run-project.mjs test`: Node標準テスト45件とVitest 866件（58ファイル）すべて成功。`build`: TypeScriptとVite成功。初回サンドボックス実行ではループバックEACCESと一時ファイルEPERMがあり、権限付き再実行で解消した。外部APIの成功検証ではない。
Dockerも固定digestのNode 24.22.1でbuild成功。ネットワーク無効のコンテナでLinux / Node v24.22.1を確認した。
