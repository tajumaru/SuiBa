## 追加した読み取り専用監査

[scripts/ml-data-audit.ts](../scripts/ml-data-audit.ts) はSQLiteのreadOnly接続とquery_onlyで、指定期間のテーブル件数、JSON不正、指標・候補・注文の結合、BUYの同じ足での繰返し、約定・評価額・停止イベントを集計する。BotDatabaseを生成しないのでschema作成・初期値保存をしない。欠落テーブルは欠落として返す。1テーブル20万行を超える窓は拒否し、黙って末尾だけ抽出しない。

```powershell
# sui-ai-trading-bot/ で実行。終了済みrunの検証済み保存コピーを指定する。
node --import tsx scripts/ml-data-audit.ts <snapshot.sqlite> <FROM_ISO> <UNTIL_ISO>
# 日時例：2026-11-07T00:00:00Z（実際のrun開始/終了へ置き換える）
```

期間はUTC等のtimezoneを必須とし、`[from, until)` の半開区間。stdoutは集計JSONのみで、rawの判断・設定・認証情報は出力しない。保存したい場合は個別のignored作業ディレクトリへリダイレクトする。入力のコピーやSHA照合はこのコマンド自身は行わない。

- `candlesAllHistory` はDB全体の在庫で、指定期間に利用できた足という意味ではない。
- `evidenceComplete` はv1の数値指標・時刻・閾値等の形式を検査する件数。実際の上流到着時刻やbuild一致まで保証しない。
- BUY重複数は単一DB内の同じ足・selectedRuleによる予備集計。pair/source/ルール版を加えた正式な学習行生成ではない。
- 結合は期間内のID一致だけ。期間外の買いに対する売りは発生し得るので、完全な往復取引数と混同しない。
- `realizedPnlOnWindowSellsUsdc` は窓内SELLの原価配賦後損益。既に費用を反映しており、feeを再度差し引かない。feeは追加手数料＋gasで、quoteに内包されたDEX費用全体を表すわけではない。
- `observedEquityChangeUsdc` は観測された最初と最後の評価額の差。run境界が未確認なので `fullRunNetPnlUsdc` はnullのまま。サンプル間の最大ドローダウンは未観測の下落を含まない。評価額ゼロも欠損扱いしない。
- 費用不明や不正な約定JSONを損益ゼロへ変換しない。`trainingReady` は常にfalseで、自動的に学習・売買へ進まない。

## 6時間ラン終了後に使うデータ

自然終了と停止証拠を確認した後、既存の承認済みバックアップ/証拠取得経路から、**そのrunに対応する整合した保存コピー**を用意する。稼働中のsqliteファイルだけをコピーしない。WAL未反映の切り取りや、検証のための停止・再起動・resetは行わない。[既存バックアップ](../apps/worker/src/paper-backup.ts)のクリーン停止/maintenance要件を迂回しない。

入力manifestに最低限記録するもの：runId、PAPER、pair、provider、開始/実際の終了/cutoff、deployのSHA・image digest、Node/lockfile識別、設定とその有効期間、停止レシートの状態、DBコピーとmanifestのSHA256、取得時刻、期間端のportfolio/markと鮮度。秘密値や環境変数一式は収集しない。

監査後に出す基準成績は、①開始/終了の評価額と純損益、②実現/未実現の分離、③原価配賦後SELL勝敗と売買回数、④追加費用/gas/内包DEX費用の区別、⑤サンプル欠損付き最大DD、⑥稼働時間・停止/回復理由、⑦BUY候補数・独立候補数・見送り数。境界や費用が不明な項目は数値を作らず不明とする。

6時間に新しく閉じる5分足は最大72本で、BUY候補数はさらに少なくなる。ポーリング数を独立サンプル数として扱わない。6時間ランだけで学習モデルの優劣を決めない。

## 最初の学習課題とラベル

最初のモデルは**BUY候補の採用/見送りのみ**。注文数量、SELL判断、ProfitGuard、risk/429/緊急停止を学習モデルに委譲しない。BTCを取引判断に使う見送り、候補比較ブランチの保留等は[DECISIONS_JA.md](DECISIONS_JA.md)どおり維持する。

1. 母集団は、同じルール版・pair/sourceにおける、判断時点で取引可能なBUY候補。安全条件で拒否されたものは別集計とし、モデルが解除できる候補にはしない。停止中のBUYや通常のNO_SIGNAL WAITを「負け」のラベルにしない。
2. 学習行は `(runId, pair, provider, ruleVersion, closedCandleTime, opportunityId)` を識別子にし、同じ足での再ポーリングをまとめる。特徴量は実行直前のモデルが実際に読める範囲で固定する。
3. 初期特徴量は保存済みcurrent/previous指標、価格で正規化したEMA差/ATR、出来高変化、判断条件。板・chain・BTC等を最初から増やさない。fillPrice、最終risk、finalAction、将来のrepair、将来損益は入力禁止。
4. ラベルは「候補を採用した場合、固定した既存の出口・guard/risk・費用モデルで終了した純損益が正か」。未実行候補には実現損益が無いため、同じ時点情報と将来系列から独立した仮想PAPER経路を再生する。見送りを勝ち/負けと自動判定しない。
5. 終了前・データ欠落・費用不明・評価上限まで未決済は打ち切り/不明。負けやゼロにはしない。上限は評価用であり、本番の強制決済条件の追加ではない。初回データ監査後にラベル仕様を固定する。
6. OHLCだけの仮想約定はモデル仮定として明記する。同じ足の高値/安値を見て都合よく約定したことにしない。既存backtestは過去の確定足で判断し次足openでモデル約定するが、Indexer到着遅延や実際の板約定までは再現しない。

候補単体のラベル改善だけでは採用しない。BUYを見送ると、その後の保有・資金・次の候補が変わるため、**モデル有無の全ポートフォリオ経路を同じ市場期間で再生して比較**する必要がある。[既存backtest](../packages/backtest-engine/src/index.ts)の純粋計算を参照し、稼働中の `savedComparison` APIは呼ばない（backtest_runsへの書き込みを伴う）。

## 学習と採用判定

最初は無選別の現行ルールを基準とし、単純なロジスティック回帰を最初の学習候補にする。複雑なモデルを並べて最良値を選ぶ探索は増やさない。特徴量変換・欠損補完・閾値選択は学習/検証期間だけで行う。

- 時間順のwalk-forwardを使い、最後の未使用期間を固定する。候補は不規則なイベントなので単純な行数分割だけに頼らず、カレンダー時刻で窓を定義する。
- ラベルの終了時刻が次の検証期間にかかる学習行を除外し、評価上限に応じた時間のgapを確保する。同じ足の候補や同じ保有に依存する行を別foldへ散らさない。
- 評価は手数料込み純損益・最大DD・資金拘束・取引数・相場区分別成績を優先する。正解率やSELL勝率だけで採用しない。USDC待機も比較対象にする。コスト増/遅延を仮定した悪化条件も確認する。
- 採用には、複数の未学習期間とPAPER並走で改善が再現し、損失・停止条件を悪化させず、費用仮定を変えても効果が残ることが必要。研究の試行回数と不採用結果も保存する。
- 収集日数だけで「十分」とはしない。独立候補数、正負ラベル、打切り割合、相場の偏り、期間別の不確実性を点検する。不足ならモデル性能を主張せず、追加収集へ戻る。

時系列分割の基礎は[scikit-learn TimeSeriesSplit公式資料](https://scikit-learn.org/stable/modules/generated/sklearn.model_selection.TimeSeriesSplit.html)に従う。ただし同機能だけで保有期間の重複排除まで自動解決するわけではない。探索回数による過学習は[Baileyらの原論文](https://www.davidhbailey.com/dhbpapers/backtest-prob.pdf)を根拠に管理する。
