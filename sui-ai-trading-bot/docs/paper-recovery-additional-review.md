# PR #17 追加安全レビュー（2026-10-26）

基準main: 1f69022。レビュー前PR head: 49c5420。修正はPR #17の既存ブランチだけに追加する。

## 発見事項

- 高: SQL主キーとJSON内IDの不一致や論理的重複を旧処理が認識しない。約定のBUY/SELLと注文の方向も未照合。
- 高: timestamp範囲外の注文・約定・照合記録が検査から外れるため、未来日時の異常記録を見落とす。
- 高: DB読み取り例外の停止が呼出元の例外処理に依存していた。停止の永続化まで失敗する場合のプロセス内注文ゲートも明示する必要がある。
- 中: 複数の配列と件数Mapを作り、履歴をソートしてから照合する。件数に対して線形以上のソート負荷と一時領域が生じる。

## 修正

operations.tsで注文・約定・照合を全件確認し、SQL ID=JSON ID、FILLEDの方向、約定1件・成功照合1件の対応、REJECTEDに約定がないこと、孤立/重複/失敗/不正状態/未来日時を検証する。ID別Mapは保持し、一時的なSQL結果はdatabase/index.tsのrowidキーセット取得で最大1024件ずつにする。負のrowidと大きな欠番も省略しない。索引による履歴の間引きや、検証済みという理由での過去省略はしない。

復旧判定全体（注文照合・既存台帳検査・最終状態確認・再開書込）をBEGIN IMMEDIATEトランザクションで保護する。別のDB接続による書換えを検査途中に許可しない。取得不能/BUSYも安全側へ停止する。全件検査後に世代番号、手動/緊急停止、障害フラグを再確認する。

読み取りまたは復旧トランザクションが失敗すればPAPER_RECOVERY_READ_FAILEDで停止を試み、プロセス内の再開不可フラグを固定する。DBへの停止書込が失敗してもordersAllowedはfalse。永続化成功と取り違えない。既存boot処理は再開意思を消去し、再起動時も停止状態にする。

市場/Sui証明不足・backoff・通信再障害時の正常周期リセット、既存の停止条件・期限・リスク制限・単一tickは維持する。
