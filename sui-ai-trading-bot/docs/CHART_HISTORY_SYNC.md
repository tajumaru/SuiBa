# 7日履歴・価格/RSI/MACD同期の設計と実測

## 事前調査（2026-10-22）

公式Skills deepbook-sdk / deepbook-overviewと既存調査を参照。公式Indexer資料:
https://docs.sui.io/onchain-finance/deepbook/deepbookv3/deepbookv3-indexer

実APIでは既存調査同様に start_time / end_time をUnixミリ秒で指定すると取得できる。公式の秒表記との相違を保持する。今回の実測は `data/chart-probe-1792624868279/probe.json` に保存した（公開市場データ、Git管理外）。

- 8日間を3ページ取得：1,000 + 1,000 + 253 = 2,253本。
- 直近7日間：1,968本、期待2,016本、未取得48本。範囲は取得できるが完全連続とは保証できない。
- HTTP 200、応答1,107 / 870 / 746ms。最古時刻−1msを次のend_timeにして後方に進む。無限ページング禁止。
- 欠損を無条件に補完しない。通常Provider由来の検証済み再構築足がある場合だけprovenanceごと再利用する。表示用取得では新たな無約定判定や再構築を行わない。

## 既存構成

market_candlesは(timeframe,timestamp,source)が主キーでJSONを保存。取得元・provenanceを保持。取得時の既存履歴削除はなく、読み出しは各時間足・最新取得元の直近1,000本に制限される。snapshotは5分足をcandlesとcandlesByTimeframeに重複して含む。既存10秒更新は変更しない。

EMA20/50は共有ema()、RSI14はWilder方式、MACD12/26/9は共有calculate()を再利用する。表示範囲を切り出す前に全履歴で計算する。欠損で分断された後は連続足から指標を再度準備し、不足中は未計測とする。

## 分離設計

- 表示履歴は別SQLiteファイル（既存DB名に.chart-history.sqliteを付加）と専用Worker thread。通常の市場データDB・検証DBはマイグレーションしない。
- 認証済みGET /api/chart/historyで時間足・from/to（Unix秒）を検証し、最大12日（7日＋ウォームアップ分）の上限を設ける。
- 取引用snapshotは拡張しない。履歴はチャートの明示操作で取得し、10秒ポーリングに載せない。
- 取得試行、タイムアウト、ページ数、再試行、待機、保存本数・保持期間に上限。期間キャッシュと同時要求集約を使用する。
- 通常市場APIの制限・バックオフ中、取得中、次回取得直前には履歴の外部取得を延期。通常tick開始時は履歴をキャンセルし、通常処理を待たせない。
- 履歴エラーは表示専用の結果として返し、Bot状態・取引監視・24時間計測のAPI統計を変更しない。
- 同じ公開Indexerを使用するため外部の共有レート制限を完全には分離できない。追加取得は明示操作のみ・少数・直列で行う。

実測snapshot：3100は1,034,794bytes（各時間足999本）、3101は999,439bytes（5分1,000本・15分720本・1時間180本）。10秒ごとでは約6MB/分（非圧縮）。今回長期履歴をsnapshotに追加しない。既存market_candlesの保持期間・実DBの保存総数は稼働DBを直接開かず、上記は返却本数として報告する。

## 実装したAPIとキャッシュ

`GET /api/chart/history?timeframe=300&from=...&to=...`（from/toはUnix秒）。既存Bearer認証を通し、時間足300/900/3600、足境界、過去14日以内、未来の終了時刻を禁止、最大12日間（7日＋1時間足120本の準備分）を検証する。応答上限4,096本。通常snapshotは変更しない。

- 別ファイル `<DATABASE_PATH>.chart-history.sqlite` を遅延作成。candles主キー(tf,ts)、取得済み範囲coverage、履歴専用cooldownメタデータを保存。既存DBへテーブル追加や履歴削除をしない。
- キャッシュ保持14日・各時間足最大6,000本、範囲キャッシュ6時間。空白範囲も取得済みとして記録し、欠損のたびに同じ要求を繰り返さない。
- 同じ時間範囲は同時要求を集約。別要求は処理中エラー。各ページ最大1,000本・最大5ページ、全体で最大6試行、各試行8秒、全体30秒、親から35秒で強制終了。
- 要求間隔2.5秒以上。通常ネットワーク障害と502/503/504は1回のみ再試行（指数待機の初回1秒＋最大250msジッター）。429ではRetry-Afterを解析して専用cooldownを保存し、その場で再試行しない。指定なしは60秒。HTTP404などは再試行しない。
- 通常取得中・バックオフ中・次回取得の12秒以内は履歴の外部要求を延期。通常tick開始時には履歴だけを中断。取引処理は履歴の終了を待たない。共有の公開Indexer側の制限・回線帯域まで完全には隔離できない。
- 既存Bot取得済みのDeepBook足はprovenanceごと再利用。GeckoTerminalの価格をDeepBook履歴に混ぜない。履歴は表示専用であり売買・鮮度判断に戻さない。

## 画面と通信量

「チャート」タブの共通操作バーから「DeepBookの7日履歴を取得」を明示操作する。時間足ごとに準備用120本を含めて取得する。取得後は受信済みデータだけで期間切替・ズーム・移動・日時選択を3グラフへ適用する。価格・RSI・MACDそれぞれの縦軸は独立する。どのグラフからのキーボード・ポインター操作でも同じ親状態を更新する。

10秒更新で長期履歴を再送しない。通常snapshotの既存通信量は今回削減していない。履歴は明示的な取得操作1回につきHTTP応答1回であり、通常DeepBookスナップショットの新しい足のみ同じ市場であれば画面内でマージする。BotがGeckoTerminalの場合は混合せず、DeepBook表示履歴の更新は手動とする。

範囲内の欠損を明示し、欠損後の指標は連続する確定足を再度準備する。EMA20/50・RSI14・MACD12/26/9は既存関数の結果と照合済み。RSI / MACDは従来チャート同様60本未満を未計測とする。価格パスのバッチ化に丸め・間引き・ダウンサンプリングは使用しない。

## 残る制約

直近7日間の実測は1,968本で、完全な2,016本ではない。48本の欠損原因をこの作業では再調査・補完していない。完全連続の2,016本表示試験は合成データで行う。公開Indexerの保持期間・利用上限の保証はない。公式資料と実APIの時刻単位差が解消した場合は契約の再検証が必要。実スマートフォンの性能・ピンチ操作は未検証。稼働中の24時間検証コンテナは更新していない。

公式資料はOHLCVのhard limitや最大保持日数を明記していない。本実装と今回の疎通はlimit=1000に制限したもので、公開APIの最大値が1000であるとの保証ではない。

## 最終テスト・性能結果

- `pnpm build`：成功（既存依存の注釈警告のみ）。
- `pnpm test`：23ファイル、344件成功、失敗0件。
- `pnpm test:e2e`：148件成功、失敗0件。375 / 390 / 430 / 1280pxで確認。
- 履歴キャッシュ11件、表示指標・バッチ描画4件のテストを追加。既存API実プロセステストにも認証、範囲拒否、キャッシュ応答前後のBot状態不変を追加。
- 既存のRiskEngine・Profit Guard・安全停止・PAPER限定・検証記録保持・再起動後停止維持のテストも成功。
- 連続2,136本（7日＋準備足）の指標計算：今回のWindowsテスト環境で約31ms。RSI / MACDの参照計算と値一致。

## 今後の改善

欠損48本の検証済み再構築を長期履歴にも拡張する場合は、別途根拠データの取得量とAPI予算を検証する必要がある。既存の再構築条件は緩和しない。通常snapshotの約1MB/10秒という既存通信量の削減も別作業で行う。公開Indexerの共有制限を完全に分離するには専用Indexer等の構成検討が必要。

今回の変更はローカルmainへコミットし、稼働中コンテナには反映しない。進行中の24時間検証の停止・更新・初期化は禁止のまま維持する。
