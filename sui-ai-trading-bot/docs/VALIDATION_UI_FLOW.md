## 現行実装から確認した操作

| 操作 | APIと処理 | 条件・結果 |
| --- | --- | --- |
| 24時間計測開始 | `POST /api/validation/start` → `ValidationRecorder.begin()` | セッション未作成、Bot停止、Profit Guard有効。開始日時と24時間後の目標日時を永続化。Botは開始しない |
| 計測終了 | 終了API・終了ボタンなし | 保存済み目標日時に到達すると評価完了。Botは自動停止しない。停止・再起動後も同じセッションを評価する |
| PAPER開始 | `POST /api/control` `{command:"start"}` | 45秒超の市場取得、通信非正常、API backoff/上限、runtimeの緊急停止/エラー、Sui接続異常/180秒超、台帳不整合をサーバーで拒否。成功でrunning=true、MANUAL_STARTを記録 |
| PAPER停止 | 同上 `{command:"stop"}` | running=false、MANUAL_STOPを記録。復旧待ちも取り消し。計測セッションを終了・削除しない |
| RESET | 同上 `{command:"reset"}` | API待機をリセット、runtimeの緊急停止/エラーを解除しrunning=false。MANUAL_RESETを記録。履歴・残高・検証を削除しない。再開は別の手動操作 |
| 緊急停止 | 同上 `{command:"emergency"}` | 既存の共通ヘッダー操作を維持。running=false、emergency=true |

根拠：`apps/worker/src/index.ts`、`validation.ts`、`operations.ts`。全APIは既存のBearer管理トークン検証を通る。取引ごとの鮮度・見積もり・利益保護・リスク・会計の検証も維持する。UIの事前表示はサーバーの安全ゲートの代替ではない。

開始順序は「Bot停止 → Profit Guardと事前GO/承認確認 → 24時間計測開始 → 開始日時確認 → PAPER Bot手動開始」。従来の設定画面の開始・停止・解除は別画面の既存操作として存在していた。計測開始は詳細診断内にあり、開始手順が分散していた。

## 事前判定と運用状態

`PAPER_RUN2_READINESS.md` の現判定はNO-GO。固定イメージでの事前確認・実際の外部通信経路の安定性確認が未完了で、別途開始承認が必要。既存APIには、この文書のGO/NO-GOや開始承認を取得・更新する機能はない。通信正常や単体テスト合格をGOとみなさない。

今回の運用検証コントロールは、このリリースの文書判定を `validationControl.ts` に明示し、NO-GOでは計測開始・PAPER開始を無効にする。画面で解除するチェックボックスは設けない。将来GOへ更新する際は、根拠・承認を文書に記録し、同じレビューでリリース判定を更新する。これは新しいサーバー承認APIではなく、このページの開始表示・操作ゲートである。既存APIや他画面の安全条件は変更しない。

| 状態 | 表示・操作 |
| --- | --- |
| 未開始 | 計測開始をステップ1、Bot開始をステップ2に表示。NO-GO、Profit Guard無効、未取得、Bot稼働中などの理由・解決方法を各ボタン直下に表示 |
| READY | 実行可能な開始操作を青。計測開始後もBotは手動で開始する |
| RUNNING | 緑・チェック付きの日本語状態。停止を赤で表示。開始の重複実行を禁止 |
| DATA_DELAYED / DEGRADED | 黄・警告記号。注文可否を正常と混同しない |
| RECOVERING | 黄・「復旧確認中（注文禁止）」。既存の複数正常周期・時間・鮮度・台帳等の確認を継続 |
| ABNORMAL_STOP / EMERGENCY_STOP | 赤・停止理由。原因解消後に確認付きRESET。その後PAPER開始を別操作で行う |
| STOPPED / MANUAL_STOP | グレー。手動停止後は通信が正常化しても勝手に再開しない |
| 評価完了 | 完了・合格と完了・条件未達を区別。Botは自動停止しない。セッションの上書き・再開始操作なし |
| 表示更新失敗 | 黄・状態不明。開始/RESET禁止。認証付き停止は可能。最終取得済みの記録を正常な現況とは表示しない |

一時的な対象通信障害は、既存の安全確認付きPAPER自動復旧の対象になる場合がある。手動停止・緊急停止・復旧上限超過などの異常停止は別であり、解除と手動開始が必要。通信障害すべてを「自動復旧」または「必ずRESET」と案内しない。

## 実際に開始する際の日本語手順

**現時点ではNO-GOのため開始しない。以下は未達事項の解消・GO判定・別途開始承認後の手順。**

1. 専用PAPER環境で管理トークンを入力し、「接続」→「運用検証」を開く。
2. 上部の「事前判定」と「次に必要な操作」を確認する。NO-GOや状態不明なら、表示された原因を解消する。画面上の操作でGOに変更しない。
3. Botが稼働中なら「PAPER Botを停止」→内容を確認→「確認して実行」。停止状態への更新を確認する。
4. 設定でProfit Guardと保存済み取引条件を確認する。変更が必要なら既存の設定保存・確認フローを通す。
5. ステップ1「24時間計測を開始」→確認内容を読む→「確認して実行」。開始日時・終了予定日時の更新を確認する。この段階ではBotは停止したまま。
6. ステップ2「PAPER Botを開始」→保存済み設定と開始承認を確認→「確認して実行」。稼働状態とPAPER実稼働時間を確認する。無効ならボタン直下の理由を解消する。
7. 「計測だけが進行しています」が出たら、Bot停止の原因を確認する。異常停止なら詳細診断で原因を確認・解消し、「RESET：停止状態を解除」→確認して実行→停止状態を確認→PAPER Botを手動開始する。一時復旧待ちなら安全確認完了を待つ。
8. 24時間経過後に、評価完了・合格条件・PAPER実稼働・停止履歴・取引証拠を確認しJSON/Markdownを保存する。「完了」だけで正常完走とは判定しない。運用を終える場合はBotを別途手動停止する。

今回の実装・テストでは、この手順を実環境に対して実行していない。
