# 2026-11-18 の失敗から学ぶこと（TradeCap Phase 1 初回一巡）

今夜、testnet の Bot の安全ゲートが開くまでに踏んだ失敗と、そこからの学び。
失敗は全部「ゲートが開く前」に起きた。お金が動いた事故はゼロ。

## 1. 「動いているはず」が一番危ない（無言の失敗）

- Windows では REAL 用コマンドが入口の判定ミスで**中身が一切実行されず、成功した顔で終了**していた（PR #335）。
- GraphQL の問い合わせが3件、今の仕様と食い違ってエラーになっていた。うち履歴取得は**エラーを「データなし」として飲み込んでいた**ため、「履歴は完全」と言いながら取り込み0件だった（PR #339）。
- 学び：エラー応答を空データとして扱う実装は禁止。入口（起動・接続・読み込み）は「本当に中身が動いたか」を別途確かめる。無言の成功を疑う。

## 2. テストが緑でも、実物とつなぐと壊れる

- 今夜の実地バグは全部、部品テスト（fake で代用）では緑だったもの。実物の SDK・実チェーン・実スキーマとつないだ Phase 1 で初めて全部出た。
- 学び：外部 API や SDK に触る経路は、fake のテストに加えて「実物との照合」を一度は通す。特に GraphQL はスキーマが変わる前提で、問い合わせを実エンドポイントで検証する。

## 3. 「まだ何も起きていない状態」が一番壊れる

- 取引したことのない口座を読むと SDK が落ちた（口座が未作成のため、PR #336）。
- 台帳は取引イベントしか知らず、**入金という出来事を表現できなかった**。入金した全額が「説明できない差分」に見えた（PR #340、開始残高方式で解決）。
- 学び：初期状態・空・ゼロ・未作成は例外ではなく通常の入力として設計とテストに入れる。モデルに無い出来事は、異常ではなく「モデルの欠け」を疑う。

## 4. 単位と形の思い込み

- DEEP の桁を取り違えた（コインは 1e6、DeepBook 内部の物差し 1e9 と混同。設計書 §5.4.1 で一度踏んだのと同じ型、PR #337）。
- SDK の返り値が「数値」ではなく「{種類, 残高} のオブジェクト」や「プール相対（base/quote/deep）」だった（PR #337）。
- 学び：金額の単位（何桁か）と返り値の形は、推測で書かず実物で1回測ってから固定する。桁違いは金額事故に直結する。

## 5. 契約の両側が正しくても、つなぐと不可能になる

- 記録する側は「候補が無い＝未評価」と書き、確認する側は「許可」しか通さなかった。両方とも単体では正しく、つなぐと**永遠に開かないゲート**になった（PR #340）。
- 学び：状態の語彙（未評価・許可・遮断）は書く側と読む側で対にしてテストする。「永遠に成立しない条件」は設計レビューで潰す。

## 6. 外の都合は設計に織り込む

- GeckoTerminal の無料枠が 429 を返し、リトライ間隔がほぼ無いため枠を溶かして止まった。DeepBook 経路は欠けに厳しすぎ（検証用の作り）で CANDLE_GAP になった。
- 学び：レート制限は「相手の事情」ではなく前提条件。リトライには間隔と上限を持たせる。取得元は複数持ち、切替が env で完結する状態にしておく（今回は Indexer の URL が固定で切替できなかった）。

## 7. うまくいったこと

- PC 側 Codex の「想定外なら止めて報告する」規律が全件で効いた。壊れたまま進んだ場面はゼロ。
- 安全ゲートは、確認が全部本物になるまで開かなかった。開いた後は再起動テスト（S1）でも開始残高が正しく効いた。
- 学び：この2つは仕組みとして正しかった。次回も「止めて報告」と「開くのは最後」を崩さない。

## 環境まわりの小さな学び

- PC の git は `git status` だけ壊れている（未解決）。当面は新規 clone＋.env と data のコピーで回す。
- ADMIN_TOKEN は32文字以上が必須だと実地で判明（起動ガード）。
- シロ側の反省：古い origin/main を読んで誤診した件（fetch を先にする）、Codex の報告が機械宛てで たじゅまる に読めなかった件（報告は平易な言葉で結論を先に）。
