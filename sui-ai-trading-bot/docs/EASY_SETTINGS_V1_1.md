# かんたん設定 1.1

基準: 最新 origin/main `4ba3485`（作業開始時に fetch と一致を確認）。

## 初めて使う人への案内

既存DBには作成時期・初回案内完了を表す明示メタデータがありません。残高、履歴件数、初期値との一致から初回利用を推測しません。指定された代替方針を採用し、カスタム選択中のすべての利用者に、控えめな非モーダルの「安全重視をおすすめ」案内と「安全重視の設定を確認する」を表示します。初回専用の自動ポップアップではありません。DBの移行やAPIの変更は不要で、保存値は自動変更しません。

## 保存状態とプレビュー

- 保存済み設定、選択中の運用スタイル、適用予定値、保存成功後の状態を分離。
- 安全重視の選択時点で、保存済み設定のコピーに既存プリセットを適用し、基本・詳細入力欄と変更前後のプレビューを更新。API保存・Bot起動は行わない。
- 「変更内容を確認」後の「安全重視を適用」または「変更を保存」で初めて既存の全設定APIに送信。既存の保存前スキーマ検証、API側検証、保存後の再取得・一致確認を維持。
- 「適用済み」は保存と再取得の成功後のみ表示。保存・再取得エラー時は日本語で失敗を表示し、二重送信を防止。
- カスタムへの切り替えは保存済み設定を基準にする。どの入力項目を変更しても、編集中の選択はカスタムへ変わる。
- 未保存変更がある切り替えでは、破棄と編集継続を選べる確認を表示。確認なしで上書きしない。保存済みに戻す操作も明示的なボタンに分離。
- 保存済みのスタイル判定は1.0の規則を維持（プリセット対象6項目の一致）。編集中の選択は別の状態で、非対象の詳細項目を変更した場合もカスタム表示になる。
- 編集中に他の操作から設定が更新された場合は、下書きを保持して保存確認を止め、最新の保存済み設定に戻してから編集できる。
- 未保存変更がある間は開始ボタンを無効化。設定保存と開始は独立。停止・ヘッダーの緊急停止は保存中も操作可能。

## スマートフォン対応

狭い画面ではモードカード・入力欄・操作ボタンを1列にし、数値入力に `inputMode="decimal"` と16px文字を指定。ボタンと入力は44px以上、カードは84px以上。ナビゲーションを折り返し、変更前後・確認・エラーの長文を折り返す。PAPER運用中、停止中、安全停止中、緊急停止中を区別する。

## テストの実行

```powershell
pnpm build
pnpm test
pnpm exec playwright install chromium
pnpm run test:e2e
```

`@playwright/test` は画面回帰検証用の開発依存のみ。製品の実行依存は追加しない。E2EではViteで実際の画面を起動し、APIレスポンスをテスト内で置き換える。実運用DB・実API・実ウォレットを使用しない。既存の `settings-api.test.ts` は別途、一時DBと実WorkerでPAPER APIを検証する。

追加の状態管理テスト: プリセット予定値、既存値の保持、モード切り替えと破棄確認、詳細編集、保存確認、失敗時の非適用、保存中の操作禁止、外部更新との衝突。

追加の描画テスト: 初期値・既存カスタム設定の両方に共通案内を表示し、初回判定や自動保存をしない。

ブラウザーテストは7ケースを375px・390px・430px・1280pxで実行。おすすめ案内、選択・ページ更新で保存/起動しないこと、予定値と保存済み値の分離、確認後の保存、保存中の二重送信防止、PAPER開始停止の独立操作、保存/再取得失敗、カスタム編集、未保存変更の破棄確認、スキーマ違反、保存中の緊急停止、横はみ出し・44pxタップ領域・数値入力キーボード指定を確認。表示確認用のスクリーンショットは `test-results/` に出力し、Git対象外とする。

## 既存機能と残る制約

Profit Guard、RiskEngine、PAPER制約、プリセットの値・適用対象、開始停止API、設定API、DBとその履歴は変更しない。実売買・秘密鍵・署名・取引送信は追加しない。

Chromiumの画面幅・タッチ操作のエミュレーションで確認しており、実機iPhone/Safariは未検証。実市場データを用いた稼働確認は今回のUI検証範囲に含めない。

UIは編集中の外部更新を検知するが、既存APIには保存時の世代番号による競合制御がない。最後の確認とPOSTの間に別画面から保存される競合は、API契約を維持したままでは完全には防げない。
