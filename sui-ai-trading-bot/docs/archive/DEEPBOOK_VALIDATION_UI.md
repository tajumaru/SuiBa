# DeepBook 24時間検証画面の表示改善

## 表示の読み方

1. 最上部で「24時間検証」と「PAPER Bot」の状態を別々に確認します。計測中でもBot停止中なら、取引判断の検証は進みません。
2. 「次に行う操作」に従います。Botが動いている場合、計測開始前に既存の操作欄で停止してください。計測開始後のPAPER開始も手動操作です。
3. 進捗・開始日時・終了予定日時は保存済みセッションとレポート生成時刻から表示します。日時は日本時間です。表示更新は既存の10秒周期です。
4. API成功率、未解決の5分足欠損、接続・鮮度、検証期間中のPAPER実稼働時間をカードで確認します。取得値のない項目は「未計測」です。
5. 通信、再構築、注文板、AI判断・安全停止、合格条件の詳細は必要なときに開きます。API失敗や欠損の警告は折りたたみの外に表示し、警告リンクから該当詳細を開けます。

## 評価範囲

- API成功率は全APIの実試行を合算した値です。各APIの値、平均・P95、HTTPステータスは「通信の詳細」で確認できます。
- 接続と鮮度は同一の意味ではありません。鮮度には既存の市場データ監視判定を使用します。
- 24時間経過は合格を意味しません。既存レポートの合否を表示し、条件未達の場合は未達項目を表示します。
- 画面更新失敗時には現在のBot状態・接続状態を不明と表示します。記録済みの値を新しい正常状態として扱いません。
- 再読み込み時には従来どおり管理トークンで再接続が必要です。進捗はブラウザー内に保存しません。

## 変更しない機能

市場データProvider、再構築、計測周期、セッション保存、合格条件、RiskEngine、Profit Guard、PAPER取引、安全停止、手動再開、LIVE拒否、SQLiteとJSON / Markdownレポートには変更を加えていません。既存の認証済みAPIで計測を開始します。画面のボタン制御に加えて、サーバー側の停止・Profit Guard・既存セッションのチェックが引き続き適用されます。

稼働中のDocker環境は今回のUI開発では更新・停止しません。セッション中の画面反映にはコンテナ更新が必要となるため、計測終了後の反映を推奨します。

## 画面確認

Playwrightは実APIをモックし、実DB・コンテナ・外部APIにアクセスしません。375 / 390 / 430 / 1280pxで未開始、Bot停止、Bot稼働、API失敗、欠損、安全停止、24時間未満、条件未達、合格、再接続後の進捗復元、稼働中の計測開始禁止、画面更新失敗を確認します。キーボード開閉、横方向のはみ出し、意図しない書き込みがないことも検証します。合格表示のケースは画面用の合成データで、実際の24時間検証完了を示しません。
