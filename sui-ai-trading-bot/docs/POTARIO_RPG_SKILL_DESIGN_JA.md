# POTARIO RPGスキル設計（案）— 2026-11-21 シロ作成

オーナーの発案（2026-11-20深夜〜21未明）：「ゲーム感覚というか、スキル！みたいなやつ」
「レベルアップしたからどうとかないと飽きる」「RPG要素がもう少しあるといい」。
サンプル4件（スキル発動／レベル一覧／ボス戦の数字画面／キャラ対面の
戦闘シーン）は提示済みで好反応。本書は設計の叩き台。

## 原則（既存の確定事項を壊さない）

1. **スキルは本物の動きの名前**。新しい判定は作らない。ProfitGuard の拒否、予測の
   宣言と判定、影の助言——既に起きている出来事に名前と見せ方を与えるだけ。
2. **レベルは「データが貯まった節目」**。飾りの経験値は置かない。上がるたびに
   実データの集計や見せ方が本当に開く。
3. **売買ルールはレベルで変えない**。影の卒業のような権限の話は、今まで通り
   証拠ゲート（件数と物差し）＋オーナー承認が先。レベルはその節目の「顔」になる。
4. **表示は情報がある時だけ**（2026-11-20 の確定パターン）。発動とレベルアップは
   実況に1回だけ出す。常時表示はパーティ欄（概要）だけに閉じる。
5. 模式の正直さは維持する（予測は計算の目安、影は記録のみ、と分かる文言のまま）。

## スキル定義（3つ）

| スキル | 実体 | 発動の瞬間 | 実況の見せ方 |
|---|---|---|---|
| まもりの盾 | ProfitGuard | 買い合図を利益不足などで弾いた時 | 金色「スキル発動」＋理由を平易に |
| さきよみ | 予測コーン | 予測を宣言した時（節目だけ） | 緑の小さい札 |
| かげの声 | 影（AI助言） | 影が助言した時（節目だけ） | 緑の小さい札 |

スキル名は **2026-11-21 決定：この3つで確定**（B案「てっぺき／みらいし／
かげの軍師」、C案「まもり／よち／ささやき」も提示のうえ A案を採用）。

「節目だけ」の定義：毎回出すと騒がしくなるので、発動表示は
まもりの盾＝毎回（滅多に起きない）、さきよみ／かげの声＝節目
（方向が変わった時、影がルールと違う判断をした時など既存の実況条件に相乗り）。

## ボス戦（画面が戦闘シーンに変わる）

相場の大きな下げを「ボス」として扱い、出現中は戦闘シーンで見せる。
今夜（2026-11-20、24h −6.8%）のような日がボス戦だった、という実感に合わせる。

### 出現条件（実データ・滅多に出ないこと）

次のどちらかで出現（**2026-11-21 決定：この数字で確定**）：
- 24時間で −5% 以上の下げ
- 1時間で −3% 以上の急落

月数回までが目安。これより頻繁だと特別感が死ぬ。

### ボスの名前（下落のパターンで決める）

- 急落型（短時間で深い）：「閃光の投げ売り」系
- じわ下げ型（長時間じりじり）：「底なしの沼」系
深さで接頭辞（例：大／真）が付く。名前は出た下げの形そのものから付ける。
（**2026-11-21 決定：この方式で確定**）

### キャラの勇者風（戦闘中だけ）

- 普段のマスコット（もふもふ雪男雫、2026-11-08 確定）は崩さない。
  戦闘シーンの中だけで、勇者の装備を上に重ねる：小さな剣と盾を持たせ、
  赤いハチマキ（案）。実況・概要など通常画面のキャラは今のまま。
- 装備はレベルや戦績で増える余地を残す（例：まもりの盾 Lv.5 で盾が金の縁に）。
  ただし見た目の段階変化は第2弾の後半でよい。

### 戦闘シーン（画面構成）

- **画面全体は乗っ取らない**。価格と停止ボタンは常に見える・触れる（安全側）。
- 実況タブの上部に「戦闘中」バナーが出て、タップで戦闘シーンが開く。
- 戦闘シーンの構成：
  - 上：ボス（名前、HPバー＝下げ始める前の高値から現在値までの戻り具合。
    価格が戻るほどボスのHPが減る）
  - 中：パーティ3人（主人公／かげの声／まもりの盾）。パーティのHP＝資産の
    ドローダウン。**ポジションを持っていない間はボスの攻撃が当たらない**
    （持っていない＝無傷、は本当の戦略的事実なので、そのまま仕様にする）
  - 下：戦闘ログ＝その間の実況を戦闘文体で（盾が弾いた、さきよみが
    先を読んだ、等は全部本物の出来事）
- 通常画面（概要・戦略・履歴）は戦闘中も今のまま変えない。
- 見た目の型はドラクエ／ポケモン風（2026-11-21 オーナー指定）：
  左に勇者風キャラ＋仲間、右にボスが向かい合い、上にボスの HP、
  下に白枠のテキストウィンドウで戦闘ログが流れる。サンプル提示済み
  （2026-11-21 未明、好反応）。ボスの絵は下落パターンごとに数種類。

### 戦闘の流れと終了

- ボスの攻撃＝さらなる下落。パーティの技＝実際のスキル発動
  （まもりの盾が悪い買いを止める、さきよみが予測を出す）。
- **勝利（耐え切った）**：価格が高値側へ戻す／下げが止まって安定し、
  出現条件を外れたら終了。「ボスを耐え切った」と戦績に記録。
- **撤退**：損失で手放した、安全停止した場合は「撤退」として中立に記録。
  「全滅」のような笑い方はしない（お金が減った事実を茶化さない）。
- 報酬：参加したスキルに経験値（まもりの盾は戦闘中の発動で多め）。
  称号（二つ名）の材料になる（例：「暴落を耐えた盾」）。

### 実装メモ

- 出現判定は worker が既に持っている価格系列（24h／1h の変化率）で可能。
  閾値は定数として持ち、設定画面には出さない（売買ルールではないため）。
- 状態は実況の新 kind と戦績レコードで保存。戦闘シーンは dashboard 側の
  表示追加のみで、worker の売買には一切触れない。

## 実装の切り分け（承認後に着手）

進め方は2弾（2026-11-21 オーナー決定：設計を固めてから実装）：
- **第1弾**：スキル発動の表示＋パーティ欄（レベル・経験値）
- **第2弾**：ボス戦＋戦闘シーン（勇者風・ボスの絵）

1. **worker**：3スキルの経験値（既存集計の読み取り）とレベル判定、
   レベルアップ検知を実況の新 kind として記録
   （narrationStorage の zod enum と NarrationState への .default() をセットで）。
2. **dashboard**：実況の発動表示（金／緑の札）、概要のパーティ欄。
3. **集計の追加**：アンロック側（外れの向き、止めた買いのその後）は
   分析マートで先に検証してから本実装（証拠ゲートの流儀どおり）。
