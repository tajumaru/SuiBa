# モバイルUI・復旧導線の改善

対象: `tajumaru/SuiBa` / `sui-ai-trading-bot`

調査開始時の `origin/main`: `8ab6e99b91628d845348da19fb6d838b8e450ae7`。
作業中のmain更新へ追従し、最終基点は `f03f7be869a28c7d4ab81dbcb2605dc852551ae3`。
専用ブランチ: `codex/mobile-recovery-guidance`。

## 原因の切り分け

バックエンドは通信状態 `HEALTHY / DEGRADED / RECOVERING` と、停止・自動再開の意図を返している。
今回の問題は主にその情報のUIへの反映にあった。

- 開始拒否の409応答を状態取得エラーに保存していたため、正常な拒否まで「状態不明」に変わっていた。
- 操作バーは `runtime` だけを参照し、通信復旧が未確認でも開始ボタンを表示していた。
- 通信による一時停止も `runtime.running=false` になるため、運用画面が通信復旧状態より先に通常停止と扱っていた。
- 注文不可を一律に「Bot停止中」「状態取得失敗」とする箇所があり、稼働状態と注文許可の違いが伝わらなかった。
- モバイルでもキャラクターを負の余白とstickyで重ねていた。吹き出しと状態表示の領域が確保されず、操作ボタンも小さかった。

バックエンドの安全判定・認証・復旧条件は変更していない。

## 状態と操作の設計

操作バーのすぐ下に「原因」「安全状態」「次の操作」をまとめた復旧ガイドを置く。
正常稼働時は操作バーに状態を表示し、復旧ガイドは省く。

| バックエンドと取得結果                   | 表示                               | 安全状態・次の操作                                                                       |
| ---------------------------------------- | ---------------------------------- | ---------------------------------------------------------------------------------------- |
| 取得失敗、または画面の状態取得から30秒超 | 状態取得失敗                       | Botの稼働・注文可否は未確認。画面からの開始を禁止。「状態を再取得」、続く場合は通信診断  |
| 初回取得中・手動再取得中                 | 通信確認中                         | 取得完了まで開始不可                                                                     |
| `DEGRADED`                               | 通信異常                           | 新規PAPER注文は禁止。`resumePending=true`なら自動復旧待ち。falseなら復旧確認後も手動開始 |
| `RECOVERING`                             | 通信確認中                         | 安全確認の完了まで開始不可。自動再開の有無を明示                                         |
| `HEALTHY`・手動停止                      | 停止中                             | 自動再開しない。保存済み条件を確認して手動開始。開始時にサーバーが再確認                 |
| 緊急停止・異常停止                       | 停止中（操作バーは停止種別も表示） | 診断→戦略の停止解除→手動開始。通信の復旧だけでは再開しない                               |
| 稼働中・注文許可なし                     | 通信確認中                         | データ・安全条件の確認中。状態取得失敗やBot停止と断定しない                              |
| 稼働中・`HEALTHY`・新規注文許可あり      | 正常稼働                           | 売買条件を満たした場合のみPAPER仮想売買                                                  |

「通信診断を開く」は運用検証タブへ移動し、詳細診断を展開して見出しにフォーカスする。
状態・運用情報の更新はGETのみで、診断を開くだけでは停止解除や再開を行わない。
自動復旧待ちには「自動再開を取り消して停止」も表示し、既存の手動停止コマンドで再開意図を取り消せる。
開始拒否は操作の近くに日本語で表示し、状態取得の成否には混ぜない。
キャラクターの実況も自動復旧待ちと手動開始待ちを区別する。

## モバイル表示

- 幅600px以下ではキャラクターを通常フローに置き、ヘッダ・状態・操作と領域を分ける。
- 吹き出しの幅を確保し、狭い画面では改行する。
- 開始・停止・解除に文字ラベルを付け、タッチ領域を44px以上にする。
- 復旧ガイドは16px本文で縦に読み進められる構造にする。
- 下部ナビのsafe-areaとページ下余白、フォーカス時のスクロール余白を確保する。
- `viewport-fit=cover` を指定し、拡大操作は維持する。

## 維持する安全仕様

- PAPER限定。実資金取引やLIVEの有効化は行わない。
- 通信異常時の新規注文禁止と、復旧未確認の開始拒否を維持する。
- 自動復旧は正常2周期・60秒以上・周期間30秒以上と、市場・Sui・帳簿・注文の整合性確認が必要。
- 180秒または9失敗で復旧を打ち切る既存仕様を維持する。
- 手動停止・緊急停止は自動再開意図を取り消す。
- 診断表示の取得を復旧証明として扱わない。
- 管理Cookie/Bearer認証、同一オリジン検証、自動検証用のBearer認証と既存CIを維持する。
