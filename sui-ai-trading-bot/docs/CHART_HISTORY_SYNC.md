## 事前調査（2026-10-22）

公式Skills deepbook-sdk / deepbook-overviewと既存調査を参照。公式Indexer資料:
https://docs.sui.io/onchain-finance/deepbook/deepbookv3/deepbookv3-indexer

実APIでは既存調査同様に start_time / end_time をUnixミリ秒で指定すると取得できる。公式の秒表記との相違を保持する。今回の実測は `data/chart-probe-1792624868279/probe.json` に保存した（公開市場データ、Git管理外）。

- 8日間を3ページ取得：1,000 + 1,000 + 253 = 2,253本。
- 直近7日間：1,968本、期待2,016本、未取得48本。範囲は取得できるが完全連続とは保証できない。
- HTTP 200、応答1,107 / 870 / 746ms。最古時刻−1msを次のend_timeにして後方に進む。無限ページング禁止。
- 欠損を無条件に補完しない。通常Provider由来の検証済み再構築足がある場合だけprovenanceごと再利用する。表示用取得では新たな無約定判定や再構築を行わない。

## 既存構成

market_candlesは(timeframe,timestamp,source)が主キーでJSONを保存。取得元・provenanceを保持。取得時の既存履歴削除はなく、読み出しは各時間足・最新取得元の直近1,000本に制限される。snapshotは5分足をcandlesとcandlesByTimeframeに重複して含む。既存10秒更新は変更しない。

EMA20/50は共有ema()、RSI14はWilder方式、MACD12/26/9は共有calculate()を再利用する。表示範囲を切り出す前に全履歴で計算する。欠損で分断された後は連続足から指標を再度準備し、不足中は未計測とする。

## 分離設計

- 表示履歴は別SQLiteファイル（既存DB名に.chart-history.sqliteを付加）と専用Worker thread。通常の市場データDB・検証DBはマイグレーションしない。
- 認証済みGET /api/chart/historyで時間足・from/to（Unix秒）を検証し、最大8日＋ウォームアップ分の上限を設ける。
- 取引用snapshotは拡張しない。履歴はチャートの明示操作で取得し、10秒ポーリングに載せない。
- 取得試行、タイムアウト、ページ数、再試行、待機、保存本数・保持期間に上限。期間キャッシュと同時要求集約を使用する。
- 通常市場APIの制限・バックオフ中、取得中、次回取得直前には履歴の外部取得を延期。通常tick開始時は履歴をキャンセルし、通常処理を待たせない。
- 履歴エラーは表示専用の結果として返し、Bot状態・取引監視・24時間計測のAPI統計を変更しない。
- 同じ公開Indexerを使用するため外部の共有レート制限を完全には分離できない。追加取得は明示操作のみ・少数・直列で行う。

実測snapshot：3100は1,034,794bytes（各時間足999本）、3101は999,439bytes（5分1,000本・15分720本・1時間180本）。10秒ごとでは約6MB/分（非圧縮）。今回長期履歴をsnapshotに追加しない。既存market_candlesの保持期間・実DBの保存総数は稼働DBを直接開かず、上記は返却本数として報告する。
